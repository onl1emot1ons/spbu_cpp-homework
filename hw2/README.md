# ДЗ 2. Умножение плотных матриц

## Реализация

`Matrix.h` задаёт общий интерфейс с виртуальными методами получения размеров, чтения элемента и умножения `mul`. Класс `DenseMatrix` реализует этот интерфейс.

Плотная матрица хранит число строк и столбцов в полях типа `int`, а элементы — в плоском `std::vector<double>` в построчном порядке. Элемент `(row, col)` находится по индексу `row * cols + col`. Перед умножением индексов выполняется преобразование к `std::size_t`.

Предусмотрены создание нулевой матрицы и создание матрицы из готового вектора. Конструкторы проверяют размеры и соответствие длины вектора форме матрицы; методы доступа проверяют индексы. Несовместимые размеры при умножении вызывают `std::invalid_argument`.

Доступны два метода:

- `multiply_naive` — порядок циклов `i-j-k`;
- `multiply_optimized` — порядок циклов `i-k-j`, с сохранением выбранного элемента первой матрицы перед внутренним циклом.

Оба метода возвращают `DenseMatrix` по значению. Внутри алгоритмов используется прямой доступ к векторам: допустимость индексов обеспечивается границами циклов и проверкой совместимости размеров.

Метод `mul` вызывается через интерфейс `Matrix`, проверяет тип второй матрицы через `dynamic_cast` и использует `multiply_optimized`. Результат возвращается как `std::unique_ptr<Matrix>`. В текущем ДЗ поддерживается Dense × Dense. В базовом классе объявлен виртуальный деструктор.

## Проверки корректности

- Маленький пример `2×3` на `3×2`: ожидаемый результат `{{58, 64}, {139, 154}}`.
- Умножение на единичную матрицу.
- Умножение на нулевую матрицу с проверкой формы результата.
- Исключение при несовместимых размерах.
- Совпадение двух реализаций на случайных матрицах нескольких размеров, включая прямоугольные.
- Вызов `mul` через ссылки на `Matrix`: проверка наличия результата, его размеров и элементов по известному ответу.

При сравнении вещественных результатов используется абсолютный допуск `1e-9`. Все тесты завершились успешно. AddressSanitizer не обнаружил ошибок при выполнении проверок в настроенном Debug-профиле.

## Методика измерений

Измерения выполнены в Release с MSVC. Для каждого размера создаётся одна пара квадратных матриц со случайными элементами из диапазона от −5 до 5. Используется `std::mt19937` с начальным значением `42`.

Каждый метод запускается три раза; в таблице приведено среднее время. Измерение выполняется через `std::chrono::steady_clock` и включает создание нулевой матрицы результата и умножение. Генерация исходных данных, подсчёт контрольной суммы и вывод не входят в измеряемые участки. В каждом повторении наивный метод запускается первым, оптимизированный — вторым; порядок не чередуется.

Результаты используются для вычисления выводимой контрольной суммы. Она препятствует удалению неиспользуемых вычислений оптимизатором, но не заменяет тесты корректности.

## Результаты

| Размер | Наивный `i-j-k`, с | Оптимизированный `i-k-j`, с | Ускорение |
|---|---:|---:|---:|
| 100 × 100 | 0.002531 | 0.001130 | 2.240286 |
| 200 × 200 | 0.019648 | 0.007391 | 2.658310 |
| 500 × 500 | 0.327355 | 0.111669 | 2.931474 |
| 1000 × 1000 | 3.421739 | 1.197305 | 2.857868 |

Ускорение рассчитывается как `T_naive / T_optimized`. Оно получено из исходных измерений до округления времени для вывода. Контрольная сумма: `-79444.882593`.

В этом запуске оптимизированная реализация быстрее примерно в 2.24–2.93 раза. При построчном хранении порядок `i-k-j` позволяет во внутреннем цикле читать соседние элементы строки второй матрицы и обновлять соседние элементы строки результата. Это улучшает использование кеша и создаёт условия для векторизации компилятором. Обе реализации выполняют одинаковое количество арифметических операций; для квадратных матриц их сложность — `O(n³)`.

Ускорение не обязано монотонно расти с размером: на измерения влияют кеш, фоновая нагрузка и другие условия. Приведённые коэффициенты относятся к данному запуску и компьютеру.
