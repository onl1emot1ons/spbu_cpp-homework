# ДЗ 3. Разреженные матрицы

## Реализация

Класс `SparseMatrix` реализует общий интерфейс `Matrix` из ДЗ 2 и хранит матрицу в формате CSR (Compressed Sparse Row).

| Поле | Тип | Назначение |
|---|---|---|
| `rows_`, `cols_` | `int` | Число строк и столбцов |
| `values_` | `std::vector<double>` | Ненулевые значения в построчном порядке |
| `col_indices_` | `std::vector<int>` | Номер столбца каждой записи |
| `row_ptrs_` | `std::vector<std::size_t>` | Границы записей строк |

Для строки `i` записи находятся в диапазоне от `row_ptrs_[i]` включительно до `row_ptrs_[i + 1]` исключительно. В `row_ptrs_` всегда `rows_ + 1` элементов, первая граница равна нулю, последняя — количеству сохранённых записей. Пустой строке соответствуют одинаковые соседние границы.

Например, матрица `{{0,5,0,2},{0,0,0,0},{3,0,7,0}}` представляется массивами:

```text
values_:      {5, 2, 3, 7}
col_indices_: {1, 3, 0, 2}
row_ptrs_:    {0, 2, 2, 4}
```

Предусмотрены конструктор нулевой матрицы и явное преобразование из `DenseMatrix`. Метод `get_element` проверяет координаты и ищет нужный столбец среди записей одной строки; если запись отсутствует, возвращает ноль. Для обхода CSR доступны константные методы `get_row_start`, `get_row_end`, `get_value`, `get_col_index`. Поля остаются закрытыми.

## Четыре сочетания типов

| Сочетание | Алгоритм | Тип результата |
|---|---|---|
| Dense × Dense | Оптимизированное умножение ДЗ 2, `i-k-j` | DenseMatrix |
| Dense × Sparse | Перебор элементов первой матрицы с пропуском нулей и записей соответствующей строки второй | DenseMatrix |
| Sparse × Dense | Перебор ненулевых элементов первой матрицы и всех столбцов соответствующей строки второй | DenseMatrix |
| Sparse × Sparse | Перебор записей обеих матриц, накопление одной строки и построение CSR | SparseMatrix |

Основное прибавление во всех случаях: `C(i,j) += A(i,k) * B(k,j)`. В Sparse × Sparse временный вектор имеет длину, равную числу столбцов результата. После обработки строки в CSR добавляются только ненулевые суммы. В частности, ненулевые произведения могут взаимно уничтожиться, и тогда запись не сохраняется.

Общий виртуальный метод `mul` возвращает `std::unique_ptr<Matrix>`. Владение результатом передаётся вызывающему коду; освобождение памяти происходит автоматически. В `Matrix` объявлен виртуальный деструктор.

Первый тип выбирается виртуальным вызовом реализации `mul` у фактического объекта. Второй определяется через `dynamic_cast` внутри этой реализации. Выбрана такая диспетчеризация, поскольку она позволяет явно различить четыре сочетания в имеющейся иерархии C++14. Для неподдерживаемого типа выбрасывается исключение. Проверка совместимости размеров выполняется соответствующим алгоритмом.

Определения `DenseMatrix::multiply_sparse` и `DenseMatrix::mul` вынесены в `DenseSparse.cpp`. Это позволяет подключить полные определения двух классов в файле реализации и избежать взаимного включения заголовков. В `DenseMatrix.h` используется предварительное объявление `SparseMatrix`.

## Структура и сборка

```text
hw2/
    Matrix.h
    DenseMatrix.h
hw3/
    SparseMatrix.h
    DenseSparse.cpp
    main_hw3.cpp
    CMakeLists.txt
    tests/tests.cpp
    bench/benchmark.cpp
    README.md
```

В корневом `CMakeLists.txt` папка подключается через `add_subdirectory(hw3)`. Внутренний `hw3/CMakeLists.txt` определяет отдельные цели `hw3_tests` и `hw3_bench`, каждая из которых собирается вместе с `DenseSparse.cpp`. У каждой программы свой `main`. Используется C++14 и CMake не ниже указанной в проекте версии 4.3.

После переноса определения `DenseMatrix::mul` файл `hw3/DenseSparse.cpp` также подключён к использующим этот класс целям ДЗ 2. Иначе отсутствующая реализация приведёт к ошибке линковки.

## Проверки корректности

Тесты вызывают умножение через интерфейс `Matrix` для всех четырёх сочетаний. Сравнение проверяет форму результата, затем элементы с абсолютным допуском `1e-9`. Неконечная разность считается ошибкой.

Проверяются:

- преобразование в CSR, значения записей, индексы столбцов, границы и пустые строки;
- прямоугольный пример `3×4` на `4×3` с вручную вычисленным результатом `{{24,0,15},{0,0,0},{0,27,0}}`;
- единичная матрица слева и справа;
- нулевая матрица слева и справа;
- исключения при несовместимых размерах;
- взаимное уничтожение слагаемых и отсутствие нулевых записей в CSR-результате;
- нулевые размерности;
- случайные матрицы нескольких размеров и плотностей, включая смешанные сочетания.

Главная кросс-проверка использует наивное умножение `DenseMatrix` из ДЗ 2 в качестве эталона. Из одних исходных данных создаются плотное и разреженное представления, после чего каждый вариант `mul` сравнивается с эталоном. Генератор имеет seed 42.

## Бенчмарк

Размер фиксирован: 500 × 500. Плотность — доля ненулевых элементов — меняется одновременно у обоих множителей. Для каждого уровня генерируется пара плотных матриц с точным количеством случайных ненулевых позиций и создаются эквивалентные CSR-копии. Seed генератора — 42, ненулевые значения выбираются из диапазона от −5 до 5.

Для каждого сочетания выполняется один прогревочный вызов и три измеряемых; выводится среднее время. Порядок сочетаний сдвигается между повторениями. Используется `std::chrono::steady_clock`.

Время включает создание результата и его вычисление, в том числе накопитель и построение CSR там, где они нужны. Генерация исходных данных, преобразование в CSR, контрольная сумма, вывод и уничтожение возвращённого результата находятся вне замера. Следовательно, сравнивается умножение уже подготовленных представлений.

## Объяснение результатов и границы выводов

При снижении плотности Dense×Dense продолжает обходить все элементы и выполнять арифметические операции с нулями. Поэтому его время преимущественно остаётся около 0.083–0.089 с. Значение 0.140681 с при 5% выбивается из ряда; по этим данным причину установить нельзя, и этот замер полезно перепроверить.

Sparse×Sparse обходит сохранённые записи обоих множителей, поэтому число произведений быстро уменьшается. Однако сохраняются затраты на обнуление и просмотр накопителя каждой строки. При плотности 0.1% в каждом множителе только 250 ненулевых записей, а наблюдаемое ускорение относительно DD составляет около 525 раз.

Dense×Sparse также пропускает нулевые элементы первой матрицы, а во второй перебирает только сохранённые записи. Sparse×Dense после выбора ненулевого элемента первой матрицы проходит все столбцы второй, в том числе нулевые. Это объясняет различие объёма работы; на время дополнительно влияют проверки доступа и оптимизация компилятором.

В этом запуске SS быстрее DD уже при 100%. Следовательно, точка перехода на исследованной сетке **не обнаружена**: нет измеренной точки, где DD быстрее, за которой SS начинает выигрывать. Можно утверждать только преимущество данной реализации SS на всех измеренных плотностях при данном размере.

Преимущество при 100% не доказывает превосходство CSR как формата для полностью заполненных матриц: сравниваемые реализации различаются организацией накопления строки и доступом к данным, что может по-разному оптимизироваться компилятором. Для локализации перехода требуется отдельное исследование других фиксированных размеров, более точные замеры или улучшение плотной реализации; заранее гарантировать существование перехода нельзя. Для защиты этот результат нужно представить честно, не называть 100% точкой перехода.

Числа относятся к конкретному запуску и компьютеру. Типы выходных матриц различаются: SS строит CSR, остальные сочетания возвращают DenseMatrix. Память и преобразование исходных форматов отдельно не измерялись.
